# T-031 Tile Art Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give grass/dirt tiles real surface art and expose brick art a castle theme can consume, entirely from `src/render/**`.

**Architecture:** Two procedurally generated 16×16 `THREE.DataTexture`s built from pure pixel functions. The ground map is grayscale so it *multiplies* with the existing per-instance palette hexes instead of replacing them; the brick map is colored so it reads as brick with no tint applied. A memoized `tileArtForTheme()` maps a `Level.theme` string to its art, and `applyTileArt()` attaches a theme's map to any mesh's material without touching `material.color` or `instanceColor`.

**Tech Stack:** TypeScript, three.js r180, vitest + jsdom.

**Spec:** `/home/box/.claude/plans/brainstorming-you-are-implementing-starry-galaxy.md`

## Global Constraints

- Scope is **exclusively** `src/render/**` plus tests under `tests/`. Do not edit `src/main.ts`, any levels JSON, `src/entities/**`, or `src/physics/**`.
- Do not monkey-patch `THREE`.
- `tileColorAt()`, `GRASS_TOP_COLOR`, `DIRT_COLOR`, `SKY_COLOR` keep their current values and behaviour. Textures are **additive**.
- `createTileLayer()` must keep returning a `MeshLambertMaterial` (non-PBR) or `tests/render.test.ts` breaks.
- Textures are `DataTexture`, not `CanvasTexture`: jsdom here has no 2D canvas backend (`node_modules/canvas` absent, jsdom 25.0.1 declares no optional deps), so `getContext('2d')` returns `null` under vitest.
- `DataTexture.flipY` is `false`. Pixel array row `0` is `v = 0`, the **bottom** of the tile quad.
- No `Math.random()` anywhere — tests assert exact texel values. Use an integer hash.
- Texture size is 16×16 RGBA for both maps.
- Ground map luminance floor is `179` (≈0.70 of 255) and ceiling is `255`.
- Import paths carry the `.ts` extension, matching the existing codebase style.

- [ ] **Step 3: Write the minimal implementation** — `src/render/tile-art.ts` per the pixel model below.

Ground luma at `(x, y)`, `y = 0` at the bottom, `fromTop = 15 - y`:
- `fromTop < 3` (the crown): `250 - fromTop * 6`
- otherwise: `214 - (fromTop - 3) * 2`
- minus `5` when `x % 4 === 0` (vertical grain)
- plus a speckle from `[-8, -4, 0, 4][hash(x, y) % 4]`
- clamped to `[179, 255]`, written to r, g and b alike, alpha `255`

Brick at `(x, y)`, course `c = floor(y / 8)`:
- `y % 8 === 0` → mortar row; `c === 0 && x % 8 === 0` or `c === 1 && (x + 4) % 8 === 0` → mortar column
- mortar is `rgb(78, 70, 64)`; brick face is `rgb(178, 90, 68)` — exactly `CASTLE_BRICK_COLOR` — shaded `±10` per brick from the same hash
- `y % 8 === 7` (a brick's top edge) adds `18` to each channel
- the per-brick index wraps modulo bricks-per-course, so the brick split across the tile seam by
  the offset course is shaded as one brick rather than two — a tiled wall shows no mid-brick
  color break
- `colorSpace = THREE.SRGBColorSpace` on the brick map only; the ground map stays linear so the multiplier curve is predictable
